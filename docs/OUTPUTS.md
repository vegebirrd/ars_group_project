# Tables, figures and interpretation

The R pipeline writes results to `outputs/r/`. Figures are in `outputs/r/figures/`. Generated output belongs in the local working directory, not in Git.

## Core tables

| File | Interpretation |
|---|---|
| `coverage.csv`, `RQ1_sample_audit.csv` | Complete events, linked Wikipedia pages, days and year/score composition |
| `RQ1_regressions.csv` | Linear score, quadratic score, pretrend, adjacent-week, medium- and long-run specifications |
| `RQ1_U_shape_diagnostic.csv` | Endpoint slopes, turning point and joint U-shape test |
| `RQ1_weekly_score_coefficients.csv` | Score association by event week |
| `RQ1_persistence_tests.csv` | Changes in score association over time |
| `RQ1_same_sample_release_models.csv` | Release-date controls on a fixed sample |
| `RQ1_robustness.csv` | Alternative event dates, baseline and timing specifications |
| `RQ1_year_adjusted_regressions.csv` | Year-adjusted main specification for the modern cohort |
| `RQ2_interaction_models.csv` | Score × baseline popularity, relative and absolute outcomes |
| `RQ2_popularity_marginal_score_slopes.csv` | Score associations at popularity quantiles |
| `RQ2_distribution_by_popularity_score.csv` | Group means, medians and cluster intervals by prior visibility |
| `RQ2_genre_interaction_joint_test.csv` | Joint test for score × genre variation |
| `RQ2_matching_balance_baseline_trend.csv` | Matching balance statistics |
| `RQ2_strict_prior_popularity_regressions.csv` | Historical Wikipedia, earlier Pitchfork recognition and chart-history interactions |
| `RQ1_consumption_regressions.csv` | Historical artist/album Spotify chart visibility |
| `RQ1_modern_chart_coefficients.csv` | Extended Spotify and YouTube chart analysis |
| `TEXT_review_language_regressions.csv` | Optional expert-review language extension |

Every coefficient table identifies the model and outcome. The per-event daily panel is **not** treated as an independent cross-sectional regression sample.

## Reading the results

1. Establish sample composition, review-score distribution and event-time trajectories.
2. Read the main conditional score association alongside the pre-review-week coefficient.
3. Compare short, medium and longer-run estimates, then release-date-adjusted specifications.
4. For RQ2, interpret marginal effects at different initial popularity levels and compare log changes with extra daily visits.
5. Examine chart visibility as a separate outcome; it captures activity among chart-listed songs, not album units sold.

The resulting findings memo, `outputs/r/RESEARCH_FINDINGS.md`, is generated directly from estimated tables by `R/08_summary.R`.
